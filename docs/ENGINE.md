# Engine guide (for scene authors)

The video is a web app (`app/`, TypeScript + three.js, run with bun + Vite) that renders any song time `t` deterministically at 1920×1080 (or at 2× that, 3840×2160, with `?scale=2`; see "Output scale" below). The same code drives the live preview and the offline 60 fps export.

This file is about the engine. What the video looks like, and which part of the song each scene covers, is in [`TREATMENT.md`](TREATMENT.md).

## Running things

- Dev server: `cd app && bun x vite --port 5173` (`bun x`, not `bunx`: the winget install of bun on Windows has no `bunx` command). Preview: http://localhost:5173/?t=23.0 (space = play/pause, ←/→ = ±1 s, shift = ±5 s, `,`/`.` = ±1 frame, `[`/`]` = previous/next timeline entry, `l` = loop the current entry, `h` = hide the UI).
- Stills (the main way to check your work — then LOOK at the PNGs with the Read tool): `cd app && bun scripts/render.ts stills --t 16.2,20,25.5 --only verse1 --out ../out/wip/verse1`
- Contact sheet of a time range: `bun scripts/render.ts sheet --from 16 --to 28 --n 16 --cols 4 --only verse1 --out ../out/wip/verse1/sheet.png`. Of the frames around every cut of the timeline (two before, two after): `bun scripts/render.ts sheet --cuts --out ../out/wip/cuts.png`
- Short video clip (to judge motion: extract frames with ffmpeg, or just trust the math): `bun scripts/render.ts video --from 20 --to 25 --only verse1 --out ../out/wip/clip.mp4 --preset veryfast` (without `--out` a video goes to `out/mv.mp4`)
- A test scene alone, off the timeline: `?scene=kit` in the preview, `--scene kit` in every mode of the render script (`scenes/_kit-test.ts`, the shared kit on screen: see "The love kit").
- `--only a,b` loads only those timeline entries (fast, and a broken scene elsewhere can't get in the way). Without a matching entry nothing renders (black), so the entry must exist in `src/timeline.ts`. The entries are `intro, verse1, chorus1, verse2, chorus2, bridge, finale, outro` (`chorus1` and `chorus2` are both `scenes/chorus.ts`, with `ctx.params.n` 1 and 2).
- Typecheck: `bun x tsc --noEmit -p tsconfig.json` (the render script: `-p tsconfig.scripts.json`).
- The render script prints `SCENE ERRORS` and browser console errors — read them.
- 4K: add `--scale 2` to any mode (`stills` then saves full-resolution 3840×2160 PNGs). Check your scene at both scales: downscaled, the 4K frame should look like the 1080p one, only sharper.
- Renders while files are being edited: run a server without live reload (environment variable `MV_NO_HMR=1`; in PowerShell `$env:MV_NO_HMR = '1'; bun x vite --port 5190`) and pass `--url http://localhost:5190`; a live-reloading server reloads the page mid-render. The private server that `render.ts` starts when none is reachable already runs without it.

## Data

- `lyrics` (`src/engine/lyrics.ts`): `lines[]` with `text,start,end,words[]`. A "word" is one sung Chinese character, `{w,start,end,at}` (`at` = its offset in the line's text), aligned to the vocal. Find lines by content, never hard-code times: `const l = this.ctx.lyrics.get('教室钟慢半拍')` → `l.words[2].start`; a line that is sung more than once takes an index, `lyrics.get('等你下课一起走好不好', 1)` for the second chorus. Helpers: `Lyrics.wordProgress(word, t)` (0..1 sung progress), `Lyrics.lineCharProgress(line, t)` (chars sung so far — for per-glyph wipes), `lyrics.findWords('见')`, `lyrics.lineAt(t)`, `lyrics.linesIn(t0, t1)`.
- `audio` (`src/engine/audio.ts`): `beats[]`, `downbeats[]`, `sections[]` (`{name,start,end}`: intro, verse1, chorus1, interlude, verse2, chorus2, bridge, final, outro), `beatAt(t)` (continuous beat index), `barAt(t)`, `timeOfBeat(i)`, `nearestBeat(t)`, `events('kick'|'snare'|'hat'|'vocal', t0, t1)`, `env(name, t)` for `rms|low|mid|high|vocal|drums|bass|other` (0..1), `hit(kind, t, halfLife)` decaying pulses.
- Every `Frame` already carries `f.a` = `{rms,low,mid,high,vocal,drums,bass,other,kick,snare,hat,vonset}` and `f.beat,f.bar,f.beatPhase,f.barPhase`.

## Writing a scene

The eight parts of the song already have their scene files and their entries in `src/timeline.ts`. A part that is not built yet is one line of `placeholder()` (`scenes/_placeholder.ts`: paper, the part's name, the lyrics by the karaoke rule), so the whole song always plays end to end. Building a part means replacing its file.

One file `app/src/scenes/<name>.ts`, default-exporting a class extending `Scene` (`src/engine/scene.ts`):

```ts
import * as THREE from 'three';
import { Scene, type Frame } from '../engine/scene';
import { FSPass, Layer2D, W, H, clearRT } from '../engine/gl';

export default class MyScene extends Scene {
  bg = new FSPass(`uniform float t; void main(){ fragColor = vec4(C_PAPER, 1.0); }`, { t: { value: 0 } });
  text = new Layer2D();
  async init() { /* build geometry, precompute text outlines, etc. */ }
  render(f: Frame, out: THREE.WebGLRenderTarget) {
    const { renderer, comp, lyrics } = this.ctx;
    this.bg.u.t!.value = f.t;
    this.bg.render(renderer, out);            // fullscreen shader → out (overwrites)
    const c = this.text.ctx; this.text.clear(); /* draw with Canvas2D */
    comp.draw(renderer, this.text.upload(), out); // alpha-over onto out
    return { vignette: 0.25 };               // post overrides (optional; the defaults are the treatment's look)
  }
}
```

Rules:

- **Deterministic**: output must be a pure function of `f.t` (and seeded randomness: `mulberry32(seed)`, `hash(...)`). Never use `Math.random()`, `Date.now()` or `performance.now()` for visuals. The export averages many sub-frames per frame, in any order (see "Motion blur and sampling"). If you need simulation state (particles, feedback buffers), set `stateful = true`, reset in `reset()`, integrate with `f.dt`, and the engine will fast-forward after seeks; such a scene can only be exported with a fixed `--samples`.
- `render()` must fully overwrite `out` (a HalfFloat linear-HDR target). Colours are **linear**. Take every colour from the palette of `TREATMENT.md` (`src/engine/palette.ts`): `rgba('rose', a)` and `mix('paper', 'peach', k)` for Canvas2D, `LIN.rose` in TS for GL uniforms, `C_ROSE`… in GLSL. No other hex colours in scenes, and no pure black.
- **Light sources and bloom:** only values brighter than white bloom, and a Canvas2D drawing never is brighter than white. To make something a light source (the sun, a lamp, a phone screen, a sparkle), draw it on a `Layer2D` of its own and add it with a tint above 1: `comp.draw(renderer, glow.upload(), out, { mode: 'add', tint: [2.2, 2.2, 2.2] })`. In a shader, write values above 1. Everything else keeps its colour: through the post chain the palette's colours come out within 2 levels (of 255) of their hex values, except `ink` and `navy`, which the lifted blacks make 4 to 8 levels lighter and warmer. Pure black would come out as `#1B1411`.
- `ctx.params` holds the timeline entry's params (one module can serve several entries); `ctx.start/ctx.end` its window; `f.lt`/`f.p` local time/progress.
- Transitions: by default the engine crossfades overlapping entries. For custom transitions set `handlesTransition = true` and composite `f.under` (the previous scene's frame) yourself using `f.tin` (0→1 over the overlap). Entries whose windows touch without overlapping cut hard. How each part hands over to the next is agreed in `TREATMENT.md`. In `src/timeline.ts` the parts' windows touch: a part starts on the beat nearest to the start of its first lyric line (found by content, no times written down), so parts cut on that beat and a part's last frame is its handoff frame. A part that needs the previous part's picture under its own way in asks for an overlap, in beats, in `OVERLAP` there; that is normally the only change a part makes to the timeline. Note that a part's first line can start a few hundredths of a second before its cut (the voice comes in just ahead of the beat).
- Post overrides you can return: `exposure, bloom, bloomThreshold, bloomKnee, bloomRadius, halation, ca, grain, vignette, lift, hud (HUD opacity, 0 by default), frame, paper, fade, flash, shake:[x,y], zoom, invert`. The defaults in `src/engine/post.ts` are the treatment's soft look and rarely need overriding: `bloom 0.45` on values above white only (`bloomThreshold 1.05`), `halation 0.1` (peach), `ca 0`, `grain 0.022`, `vignette 0.18`, `lift 0.15` (blacks lifted to a warm brown). The treatment rules out camera shake, flash frames and visible chromatic aberration: leave `shake`, `flash` and `ca` alone. `fade` goes to (lifted) black; a fade to paper is something the scene draws.
- Performance: aim for < 25 ms/frame. Canvas2D layers cost ~2–4 ms to upload each; don't use more than 2–3 per scene (the kit's `Stage` is two). Precompute in `init()`. What is too far off to be seen moving (a row of trees, a town, shop fronts) is best painted once into a canvas of its own and blitted (`strip()` in `scenes/chorus-sets.ts`, the far rows in `scenes/intro-classroom.ts`): ten dappled trees painted afresh each frame cost 20 ms. A crowd is sprites painted once (`drawWalker` in `scenes/verse2-sets.ts`), no larger than they are seen: two dozen full-size ones drawn with `imageSmoothingQuality = 'high'` cost 20 ms too.
- In a dark picture, put soft light (a phone's glow on a face, moonlight across a wall) on the picture itself, and only the source's bright heart on the light layer: the faint edge of a glow on the light layer has only a few of its 8-bit levels, and after the multiplication they show as bands in the dark.
- The light layer has no depth: it is added over the whole picture, so a lit window or a lamp shines through whatever stands before it (a bus, a wall, the two of them) unless it is taken off the layer again there. Paint what glows far to near, and cut the shapes of what is nearer out of it as you go (`globalCompositeOperation = 'destination-out'`: flat shapes for the set, `solid()` in `scenes/chorus-sets.ts`; for figures, the canvas they were painted on, which costs a fifth of drawing them again as silhouettes).
- Keep a part's code in its scene file and its own helper files (`scenes/<name>-*.ts`). Code that several scenes share lives in `src/engine/` and in scene files whose name starts with `_`; change those, and `src/timeline.ts`, only when the part's prompt calls for it, and say so in your final message.

## The love kit (`src/scenes/_love.ts`)

What every part draws with, so the parts look like one film: the two characters, their props, the air and the light, the lyric renderer, the stage and the transitions. Import it from `./_love` (its code is in `scenes/_love-*.ts`). **`?scene=kit`** shows all of it on eight pages of 8 s (`scenes/_kit-test.ts`: her poses, his poses, the design sheet, the two together, particles, lyric styles, light and depth, transitions; the two pose pages go through summer, autumn and winter clothes, at 1, 4 and 7 s into the page); as stills: `bun scripts/render.ts stills --scene kit --t 4,12,20,28,36,44,52,60 --out ../out/wip/kit`. Everything in it is a pure function of the time you hand in (and a seed).

```ts
import { Stage, drawGirl, drawLyric, dustMotes, layer, lightShaft, type Cam, type Shaft } from './_love';

export default class Verse1 extends Scene {
  stage = new Stage(this.ctx);
  override handlesTransition = true;                     // only if it comes in through stage.enter()
  render(f: Frame, out: THREE.WebGLRenderTarget) {
    const { c, g } = this.stage.begin();                 // c: the picture. g: the light (it blooms)
    const cam: Cam = { x: 30 * Math.sin(f.t * 0.2), zoom: 1 + 0.03 * f.p };
    layer(c, { cam, depth: 0 }, (c) => { /* the sky: paint the whole frame */ });
    layer(c, { cam, depth: 0.3, blur: 3, haze: 0.4 }, (c) => { /* far buildings */ });
    layer(c, { cam, depth: 1 }, (c) => {
      drawGirl(c, 'walk', { x: 900, y: 960, facing: 'right', t: f.t, walk: f.beat, outfit: 'autumn', wind: 0.3, shadow: 1 });
    });
    const shaft: Shaft = { x: 1400, y: 0, angle: -0.6, length: 1100, width: 220 };
    lightShaft(g, shaft, { alpha: 0.1, t: f.t });
    dustMotes(g, f.t, { shafts: [shaft] });
    drawLyric(c, this.ctx.lyrics.get('教室钟慢半拍'), f.t, { x: 960, y: 300, size: 84, style: 'chalk' });
    this.stage.enter(f, out, { kind: 'iris', x: 960, y: 540 });   // or this.stage.end(out)
  }
}
```

- **Characters:** `drawGirl(ctx, pose, params)` and `drawBoy(ctx, pose, params)` draw her and him; `drawStudent(ctx, pose, { boy?, silhouette? })` a background student as one flat colour (put those on a `layer` with a little blur). Never draw the two any other way. Their look was approved on 2026-10-09: fix what is wrong in a pose, but don't restyle them unless asked.
  - `pose`: `'stand' | 'walk' | 'run' | 'sit-write' | 'chin-on-hand' | 'pack-bag' | 'turn-smile' | 'wave' | 'hold-phone' | 'hold-umbrella' | 'lean-closer' | 'face-each-other' | 'point' | 'talk' | 'pocket' | 'reach'`, or `{ from, to, k }` to ease from one pose into another (a head turn in three or four steps: ease `k`, `headTurn` and `smile` with `keys()`).
  - `params`: `x, y` (the floor under the hips), `scale` (1 = about 615 px tall; he is 5% taller), `facing` (`'right' | 'left' | 'front' | 'back'` or degrees: 0 = toward the camera, 90 = right, 180 = away), `t` (breathing and sway), `wind` (-1..1: hair, skirt, ribbon, scarf), `outfit` (`'summer'`: short sleeves; `'autumn'`, the default: her cardigan; `'winter'`: her long coat, his jacket and the rose scarf), `scarf` (`false` on him while she keeps it, `true` on her), `blush` (0..1), `walk` (stride phase in cycles of two steps: pass `f.beat` for two steps a beat), `headTurn` / `nod` / `tilt` (degrees), `smile` (0..1; above 0.5 the eyes close into ◡, unless `openEyes` keeps them round), `k` (the pose's own amount, below), `bag` (the backpack; off by default when sitting or lying), `shadow` (0..1 on the floor), `light` (where the rim light comes from, or `null`), `silhouette`, `alpha`.
  - `k` and `walk` by pose: `pack-bag` k 0..1 = the book going into the bag; `turn-smile` k 0..1 = how far he has turned (toward the camera's side, smiling as he does); `lean-closer` k -1..1 = how far it leans (+ = to its own left); `wave` uses `walk` as the swing of the hand; `hold-umbrella` and `lean-closer` walk if `walk` is given and stand otherwise; `point` k 0..1 = the arm on the camera's side going out at something in front of it and lower down; `pocket` k 0..1 = the right hand going to the coat pocket (the `pocket` anchor), the eyes after it; `reach` k 0..1 = both hands going out and up to the neck of somebody who stands facing it (she puts his scarf round it); `talk` moves both hands by itself (with `t`), and walks if `walk` is given.
  - Every call returns the screen positions of `head, top, chin, neck, chest, hip, handL, handR, footL, footR, eyes` (with `eyesSeen`), `zip` (the pull of the bag's zipper pocket) and `pocket` (her coat pocket): hang props, sparkles and stars on those.
  - A pose can be seen from any side: the figure is a jointed puppet that is projected for the way it faces. There is no camera height, so put rows of desks or people further back by drawing them higher and smaller yourself. Drawn very large (a close-up: over about 3.6 times its size, by `scale` or under a camera), its round shapes get more facets by themselves.
- **Props:** `atDesk(ctx, params, () => drawGirl(ctx, 'sit-write', params))` draws a seated figure with its chair and desk in the right order (`drawDesk` / `drawChair` alone; the desk top is `DESK_TOP` units above the floor, in front of the figure); `drawPen(ctx, x, y)`, `drawPhone` + `phoneGlow` (on the light layer), `drawUmbrella(ctx, { x, y, scale, tilt })` at a hand (draw it after the people under it), `drawBag(ctx, { x, y, zip })` (a bag seen from its front: `zip` 0..1 opens the pocket; returns its `mouth` and `pull`), `drawStar(ctx, x, y, r, rot)` (the folded paper star), `drawClock(ctx, x, y, r, { time, sec })` (the classroom wall clock, the same in every part; a large one gets numerals and minute marks) with `sec: clockTick(f.beat, late)` for its second hand (`late` 0.5, the default, is the clock that runs half a beat slow; 0 ticks on the beat).
- **Depth:** `layer(ctx, { cam, depth, blur, haze, hazeColor, alpha }, draw)` is one parallax layer. `depth` 0 = infinitely far (it never moves), 1 = the subject, above 1 = close to the lens; `cam` = `{ x, y, zoom, roll }`, the slow camera of the shot; far layers get `haze` (lighter, less saturated) and a `blur` of 2 to 4, things passing close to the lens a blur of 6 to 12. Paint a shot far to near in 3 to 6 layers; don't call `layer` inside another layer's `draw`. `camera(ctx, cam, depth)` is the transform alone.
- **Light** (on `g`, the light layer, unless noted): `glow(g, x, y, r)` for the sun, a lamp or a lit window; `lightShaft(ctx, shaft, { alpha })` on the picture (it tints what it crosses) and faintly on `g` (it glows); `lightLeak(g, amount, { from })`, 0..1, 1 = the frame is washed; `sparkle(g, x, y, r, k)`; `soundRing(ctx, x, y, r, { alpha, fill })`, a sound ring of the bell (on the picture, and faintly on `g` so that it glows; `fill: 1` makes it a soft paper disc). `paperGrain(ctx, { x, y, w, h })` puts paper fibres on a sheet inside the picture (the whole frame already gets a paper texture from the stage); `dottedPath(ctx, points, k)` is the dotted-path motif; `frost(ctx, { x, y, w, h }, k, { seed })` is frost on a pane of glass (on the picture), `k` 0..1 of the way over it: at 1 nothing shows through, and the same seed gives the same frost at any size.
- **Particles** (each `(ctx, t, { x, y, w, h, count, seed, wind, alpha, size, color })`, the area defaulting to the frame): `dustMotes` (with `shafts` they only show in the light), `chalkDust` (drifting; or with `from` puffs leaving the chalk), `petals`, `leaves`, `paperScraps`, `snow`, `rain` (with `ground` each drop leaves a splash), `paperStars` (rising; or with `from`, `since`, `rate` leaving a point one by one). The defaults are sparse on purpose: they drift, they never swarm.
- **Lyrics:** `drawLyric(ctx, line, t, { x, y, size, style, ... })` draws one line by the karaoke rule and returns its characters as drawn (`x, y, sung, since, …`, to hang dust or sparkles on the one being sung). `style`: `'plain'` (the characters change colour), `'hand'` (each is written in as it is sung), `'chalk'` (written in, in chalk: for the blackboard, settles to paper), `'grid'` (handwriting in composition-paper squares). Other options: `dark` (settle to paper), `rows: 2` (break at the line's space; a line wider than `maxWidth` breaks by itself), `align`, `angle`, `hold` / `until` (when it fades), `ghost` (opacity of unsung characters, 0 = they appear as sung), `slow` (a held note is written in for as long as it is held, not in 0.45 s), `path: (u, k, n) => ({ x, y, angle?, scale? })` (floating text along a path), `each: (ch) => { … }` (move or recolour single characters). Call it every frame the line may be on screen. The rule itself (0.4 s lead at 35%, rose from the character's own start, ink or paper after the line) is built in: don't reimplement it.
- **Stage and transitions:** `new Stage(this.ctx)`, then each frame `const { c, g } = stage.begin()`, paint, and `stage.end(out)`: the picture goes over a paper texture and the light layer is added at 2.2 times its colours, so only what is painted on `g` blooms (`end(out, { light: 0 })` if nothing was). A scene that comes in from the one before sets `handlesTransition = true` and ends with `stage.enter(f, out, move)` instead: `{ kind: 'dissolve' }`, `{ kind: 'leak', from }` (light blooms in from a side, washes the frame, clears to the new picture) or `{ kind: 'iris', x, y, r?, soft?, close? }` (the new picture inside a circle: for match cuts on a round shape; give `r` each frame to drive it). `transition(ctx, move, texA, texB, out, k)` is the same between any two textures. `INTRO_RING` (`{ x, y, r }`) is the intro's handoff to verse 1: the bell's last ring as a soft paper circle that covers the frame (`soundRing(c, x, y, r, { fill: 1 })`; the intro's last frame is all paper), centred where verse 1's clock face is. `VERSE1_WASH` is verse 1's handoff to chorus 1: its last frame is one flat colour, `VERSE1_WASH.under` (a pale gold), with nothing on the light layer; the light that washed the frame there was `lightLeak(g, amount, VERSE1_WASH)`, so chorus 1 starts on that colour and lets a leak of the same colours clear off its own picture. `CHORUS1_FROST` (`{ x, y, w, h, bar, seed, trim }`) is chorus 1's handoff to verse 2: her bedroom window frosted over, so close that its glass (`x, y, w, h`, larger than the frame) covers the frame. Chorus 1's last frame is `frost(c, CHORUS1_FROST, 1, CHORUS1_FROST)` under the cross of the window's bars (one upright, one level, `bar` px wide, flat `trim`, through the middle of the glass), with nothing on the light layer; verse 2 starts on the same glass as its corridor window and lets the frost go back. `VERSE2_LAMPS` (`{ sky, at, halo, soft, heart }`) is verse 2's handoff to chorus 2: the sparkles in his eyes have become four lamps in the sky of the blue hour, and nothing else is left. Its last frame is `sky` down the frame (a linear gradient, stops at 0, 0.55 and 1) and, for each lamp of `at`, `glow(c, x, y, halo, { alpha: soft })` on the picture and `glow(g, x, y, heart)` on the light layer; chorus 2 starts on the same sky and the same four lights and puts its street under them. `CHORUS2_DESK` (`{ cam, zip, room }`, in `scenes/chorus-sets.ts`, beside the picture it is of) is chorus 2's handoff to the bridge: her desk under its lamp, her bag on her chair before it, snow in her window. Its last frame is `drawBagShot(c, g, { t, ...CHORUS2_DESK })`; the bridge starts on that call, cools the lamp with `room.warm` (1 → 0) and goes on back and up with `cam`. `BRIDGE_RAIN` (`{ at, sky, rain }`, in `scenes/bridge-sets.ts`) is the bridge's handoff to the finale: one drop of rain has landed on the glass of the classroom clock, at `at`, and its first ring has gone out over the whole frame; inside it it rains. The bridge's last frame is `drawRainIn(c, g, { t, since, cover })` and nothing else: `sky` down the frame (a linear gradient, stops at 0, 0.5 and 1), the kit's `rain` with the options `rain`, and three more rings on their way out; nothing on the light layer. The finale starts on the same call (`since` = `t - rainHit(lyrics)`, `cover` = its own start less `rainHit(lyrics)`, `null` for `g`) and puts its gate under it.

## Toolbox

- `gl.ts`: `FSPass(frag, uniforms)` fullscreen GLSL3 pass (has `vUv`, writes `fragColor`, gets `GLSL_COMMON`), `Compositor` via `this.ctx.comp.draw(renderer, tex, target, {mode:'normal'|'add'|'screen'|'multiply'|'max', opacity, tint, scale, offset})`, `Layer2D` (1920×1080 logical Canvas2D → texture; it holds the canvas's sRGB values, which `comp.draw` and the kit's `Stage` decode: a shader of your own that samples it must call `toLinear`), `makeRT()` (screen-sized HDR target; `makeRT(w, h)` takes logical px), `clearRT(renderer, rt, [r,g,b])`, `SCALE`/`PW`/`PH` (output scale and physical size).
- `palette.ts`: the ten tokens of the treatment (`HEX`, and `LIN` as linear RGB), `rgba(token | hex, alpha)` and `mix(a, b, k, alpha)` (the colour between two, for gradients, moods and lighter far layers) as CSS colours.
- `glsl/common.ts` (`GLSL_COMMON`, prepended to FSPass; import it into your own ShaderMaterials): the palette as `C_PAPER, C_INK, C_BLUSH, C_PEACH, C_GOLD, C_SKY, C_DUSK, C_NAVY, C_FROST, C_ROSE` (linear), `hash*`, `snoise(vec2|vec3)`, `fbm`, `curl2`, 2D/3D SDFs, `smin`, `aaFill`, `aaStroke`, **`hatch(u, darkness)` and `engrave(uv, darkness, freq, angle)`** for engraving-style shading (`hatchD(u, darkness, du)` takes the derivative of `u` from the caller, for a coordinate whose `fwidth` lies, such as an angle that wraps), `toSRGB/toLinear`.
- `lines.ts`: `LineBatch(capacity, {screen2D, worldWidth, blend})` — GPU capsule segments, 2D pixels (y down) or 3D with a camera. `seg2`, `seg`, `polyline`, `render(renderer, out, camera?)`. Colours linear, can exceed 1 for glow. Good for 10k–200k segments.
- `type.ts`: fonts. The video's fonts are **`F.hand(weight)`** (LXGW WenKai 霞鹜文楷, weights 300/400/500: the lyrics, the title, anything written by hand) and **`F.sans(weight)`** (Noto Sans SC, weights 400/500/700: small UI text such as chat bubbles and labels). Both are subsets: read "Typography" below before drawing a character that is not in the lyrics. `font(family, px)` → CSS font string. `layout(text, family, size, tracking)` → per-glyph x/advance (draw glyph i at `glyphs[i].x`; Chinese text has one glyph per character, and for a lyric line `line.chars[i]` says which sung character glyph i belongs to). `glyphX(text, i, family, size)` → where to start drawing `text[i..]` when a line is drawn in pieces (sung/unsung colours, wipes). `fitSize`, `measure`, `textPath2D` (opentype outline as Path2D), `textPathCommands`, `textPoints(text, family, size, step)` (points filling the glyphs: text made of dust), `missingGlyphs(text, family)`, `isCJK(ch)`, `CJK_MID`, `smart(s)` / `plain(s)` (typewriter quotes → typographic ’ “ ” … and back). The Latin fonts the engine came with are still registered (`F.archivo(width, weight)`, `F.archivoItalic()`, `F.serif(weight, italic)`, `F.mono(weight, italic)`); the treatment does not use them.
- `stroke.ts`: single-stroke plotter/engraving fonts (`script`, `hscript`, `sans`, `readable`, `tech`, `serif`, `osmotron`, `felix`): `strokeText(text, font, size, tracking, kern)`, `drawStrokeText(ctx2d, st, lengthPx)` → returns pen head position, `writtenLength(st, charTimes, t)` to sync writing to word timings. The fonts have no kerning tables: pairs that leave a hole (To, Yo, We, AV, LT…) are kerned optically from the glyph shapes (off for the connected scripts).

## Typography

Which font goes where, and the karaoke rule for lyrics, are in `TREATMENT.md` ("Typography and lyrics"). What the engine gives you:

- **The Chinese fonts are subsets.** `F.hand()` and `F.sans()` hold only the characters of the lyrics and of 《下课再见》, Chinese and keyboard punctuation, digits, Latin letters, a few signs (× ÷ ± ≠ ≈ ≤ ≥ √ ² ³ π ∞ ° △ ∠ ♪ ♡ ♥ ★ ☆ → ← ↑ ↓) and the list `EXTRA` in `analysis/make_fonts.py` (now the characters of a date, 年月日星期二三四五六, and 噢 for the message she types in chorus 1). Any other character is drawn in a fallback font and looks wrong. `layout()` and `measure()` log a console warning that names it (render.ts prints it under BROWSER LOG); text drawn with `fillText` alone is not checked, so check new strings with `missingGlyphs(text, family)`.
- **To add characters:** append them to `EXTRA` in `analysis/make_fonts.py`, run `cd analysis && uv run python make_fonts.py`, and commit the font files it rewrites in `app/public/fonts/`. The first run downloads the full fonts (about 100 MB) into `analysis/.cache/fonts/`.
- **Per-character drawing:** a Chinese character is as wide as the font size and has no kerning (`isCJK(ch)`), so `layout(line.text, F.hand(), size).glyphs[k]` sits at `k * size` until a narrower character comes: the curly quotes “ ” and the space (in `慢慢走 慢慢讲`) are about 0.35 of the size in LXGW WenKai. Always take positions from `layout()`, not from `k * size`.
- **Which character is being sung:** a sung token (`Word`) is one Chinese character plus the punctuation attached to it (`“明`, `见”`). `line.chars[k]` is the k-th character of the text with its token (`.word`, or `null` for a space), so glyph k of the layout is sung when `t >= line.chars[k].word.start`; `Lyrics.wordProgress(word, t)` runs 0..1 through it, and `Lyrics.lineCharProgress(line, t)` gives the characters sung so far for a wipe across the line.
- **Vertical placement:** place text by its baseline (`textBaseline = 'alphabetic'`). The ink of a Chinese character is centred about 0.36 of the font size above the baseline in both fonts (`CJK_MID`), reaching up to about 0.85 above and 0.15 below. To centre a character on (x, y), as in a grid square: `textAlign = 'center'` and `fillText(ch, x, y + CJK_MID * size)`. Don't use `textBaseline = 'middle'` for this: it sits 2 to 6% low, by a different amount in each font.
- **Punctuation:** `Word.w` and `Line.text` go through `smart()`; `lyrics.get()` matches straight or curly quotes. Hardcoded display strings use ’ “ ” … — too.
- `util.ts`: `clamp, lerp, remap, smoothstep, ease.*` (the treatment's `ease.inOutSine` and `ease.inOutCubic` among them), `prog(x,a,b,ease), keys(t, [[t,v,ease],...]), springStep, pulse, mulberry32, hash, noise1/2/3, fbm1/2, polylineLengths, pointAtLength, window01`.
- `hud.ts`: a global overlay over every scene. It only has crop marks and is hidden by default; a scene shows them by returning `hud: 1` and `frame: 0..1`.

## Output scale (4K)

`?scale=2` (render.ts `--scale 2`) renders a true 3840×2160 frame. Scenes keep laying out in logical 1920×1080 px (`W`, `H`, `ctx.W`, `ctx.H` never change); the engine handles the rest:

- Render targets: `out`, the engine's targets and `makeRT()` are physical (`PW`×`PH`). `makeRT(w, h)` takes logical px and allocates `w*SCALE`×`h*SCALE`; pass `{ pxScale: 1 }` for a data-sized target whose resolution must not follow the output.
- `Layer2D`: the backing canvas is `SCALE`× larger and its context is pre-scaled, so drawing code works in logical px. `setTransform`/`resetTransform`/`getTransform`, `shadowBlur`, `shadowOffsetX/Y` and `filter` px lengths are patched to stay logical. Not patched: `canvas.width/height` and `getImageData`/`putImageData` are physical px, and `drawImage(layer.canvas, x, y)` needs an explicit size. `new Layer2D(w, h, 1)` makes a deliberately low-res layer (e.g. a soft glow). `scaleContext2D(ctx, SCALE)` applies the same patch to your own canvas.
- `LineBatch`: coordinates and widths stay logical; the AA feather and the hairline floor work in physical px, so hairlines stay crisp.
- GLSL (`GLSL_COMMON`): `gl_FragCoord`, `fwidth` and `dFdx` are physical. Use `FRAG_PX` (the fragment position in logical px) instead of `gl_FragCoord.xy` whenever it is combined with logical sizes, and `PX_SCALE` to convert. A line whose width comes from `fwidth` ("a 1.2 px hairline": `1.0 - smoothstep(a, b, d / fwidth(u))`) gets thinner and fainter at 4K: write it as `pxLine(d, a, b)`, which is identical at 1× and keeps the 1× ink with sharper edges at 4K (`rampLine` does the same for the linear-ramp idiom). `hatch`, `engrave` and `aaStroke` already do this. LOD thresholds and supersampling offsets expressed in pixels should be logical (`fwidth(u) * PX_SCALE`, offsets `/ PX_SCALE`).
- Offscreen canvases used as textures (atlases, text planes) keep their own size: make them `SCALE`× larger (with `ctx.scale(SCALE, SCALE)`) if they are shown large, or they look soft at 4K.
- Post (bloom, halation, CA, grain, vignette) and the HUD scale automatically; the bloom pyramid stays at the logical resolution.

## Motion blur and sampling

The export renders every frame as the average of many sub-frames spread over the shutter (`--shutter 0.2`: a fifth of the frame time, centred on the frame's time), before post-processing. `--samples N` takes N evenly spaced sub-frames; `--samples auto` chooses the count per 32×32-logical-px tile (`Engine.render`, `AdaptiveSampling`):

- The count steps through 4, 12, 36, 108, 324. Each step adds a sub-frame either side of every existing one, so each set is evenly spread and centred on the frame's time.
- After each step the engine compares the new sub-frames' average with the old ones' (displayed values, worst 2×2-logical-px block). Stepped copies of a moving edge differ between the two sets; a converged streak or a still image does not. Stepping shrinks as 1/count, so the remaining error is about half the change the last step made; a tile stops when that is below `--tol` (default 3 levels of 255) in it and its 8 neighbours. A tile that has stopped is final: it is the average of its first n sub-frames, the image the per-frame sampler would give had it stopped at n.
- Later sub-frames skip the tiles that have stopped: the engine writes the tiles still refining into the depth buffer of its targets, and while it renders a sub-frame every draw into them is depth-tested against that mask, whatever the material says, so the GPU rejects the stopped tiles before shading them (early-Z; a stencil test does not reject early on Apple GPUs). The final average weighs each tile by its own count.
- In practice a still frame stops at 12, ordinary camera motion at 36, and whips, slams and fast zooms at 108 or 324. At 1:1 in 4K, 108 can't be told from 324, while 36 still shows faint striations on the fastest edges.
- `refine: 'frame'` (`--refine frame`) decides for the whole frame at once, as before tiles: every tile then takes the count its worst tile needs.

What this asks of scenes:

- Sub-frames are rendered out of time order and in any number: a scene's output must depend on `f.t` only. `stateful` scenes can't be sampled adaptively (the engine refuses); nothing may count `render()` calls.
- Per-frame flicker and jitter keyed to 60 fps must use `frameIdx(t)` (`util.ts`), not `Math.floor(t * 60)`. `frameIdx` is constant over the frame's shutter; `floor` switches at the frame's own time and double-exposes two states in every frame.
- Noise that changes with continuous `t` (a hash seeded by time) is resampled in every sub-frame: it averages out, but slowly, and makes the adaptive sampler work harder. Seed it with `frameIdx(t)` unless it is meant to smooth out.
- A particle emitter whose rate varies over time must take the rate as a function of each particle's birth time. A rate read at the current `t` re-times every particle from one sub-frame to the next.
- Shaders that supersample internally (4 rotated-grid taps) take `ssTap: SS_TAP` and `${SS_TAP_GLSL}` and loop `for (int k = ssK0(); k < ssK1(); k++) ... rgss(k)`, weighting by `ssWeight()`. The engine then hands each sub-frame one tap, cycling them (every set is a multiple of 4), which averages to the same image for a quarter of the cost. In the preview and single-sample stills they take all four.
- Post parameters (shake, flash, zoom, fades, the HUD mode) are read at one point of the shutter, 1/8 of it after the frame's time (where the video was tuned, and a point every sample set includes); the HUD, grain and dither are drawn once per frame.
- Masked tiles keep what the last sub-frame drew there. That is safe for `out` and the engine's own targets. A scene's own target keeps being drawn in full (and costs full price) unless the scene lists it in `tileMasked`: only a target with a depth buffer whose texels are read back at their own screen position or within a few px of it (`margin: 1` widens the mask by a tile), such as a half-resolution buffer of the same view, or, with `moving: true`, one read through a zoom or pan that the scene gives before each sub-frame's draws with `ctx.mapTileMask(rt, map)` (`null` while it is read some other way). A target read through a warp or a wide blur must not be listed.
- A draw into a masked target whose material asks for its own depth test (3D with a depth buffer) can't use the mask: the engine draws that sub-frame again unmasked and keeps drawing that scene unmasked.
